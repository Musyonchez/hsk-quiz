# Audit round 3 (Aug 14, 2026): re-check via the docs/51 playbook

First real run of the reusable process in
[51-multi-agent-audit-playbook.md](51-multi-agent-audit-playbook.md), against `main` immediately
after that playbook was written. Five parallel read-only lenses, each told to check the two prior
rounds first ([40-45](40-project-audit-overview.md), [50](50-full-sweep-audit-2026-08.md)) so they
report what those rounds missed or what's drifted, not repeat them.

No app code has changed since docs/50 was written — the only commits since are docs-only (the
docs/51 playbook itself). So four of the five lenses were, correctly, pure re-verification passes
rather than fresh sweeps against changed code, and coming back clean was the expected outcome, not
a shortfall. The fifth (docs consistency) still found real drift, because docs can go stale even
when the code they describe hasn't moved — a fix landing without its doc being updated, or a
reorg's rename missing one reference.

## Backend & data — clean, no new findings

Re-verified every route under `src/app/api/**`, `src/lib/**`, `src/lib/auth/**`, and the schema
against docs/41/50. Everything previously marked ✅ Fixed is confirmed still fixed live: the
`Friendship.@@index([friendId, status])`, the cron purge route's fail-closed auth, the removed
`getChapterDialogLineCount` dead export, `/api/attempts`'s rate limit, and the
`sendResetPassword`'s `.catch()`. Auth checks, input validation, and error-response shape were
re-traced route by route with no new gap. The already-known, already-accepted low-severity items
(no transaction around friend-request accept/ignore, `parseQuizKey` not FK-validated,
`backfill-mnemonics.ts`'s sequential awaits) are unchanged, not re-flagged as new.

## Frontend & components — one new Low finding

Re-verified the runner-quartet's shared hooks/components, dead-code surface, and a11y state
against docs/42/46/50 — all still correct, no drift.

One candidate finding was investigated and disproven rather than written up: `CharacterQuizRunner`
looked, on a first pass, like it was missing the pre-start word-preview table the other three
runners have. Tracing its actual mount path (`CharacterIsland.tsx`) showed the preview is provided
upstream by `CharacterBrowse`, which always renders first — parity is maintained at the flow
level, just via an earlier component, not missing. Worth recording as the kind of check the
playbook's evidence discipline exists to catch, alongside docs/50's mnemonic-wiring correction.

**New — Low.** No Tab-key focus containment in `LogoutButton.tsx`'s and `CharacterBrowse.tsx`'s
modal dialogs. Both already have initial-focus, return-focus, and Escape-to-close (fixed per
docs/42 §5) — what's still missing is cycling `Tab`/`Shift+Tab` back into the dialog, so a keyboard
user can tab past the last focusable element (or shift-tab before the first) out into the page
behind a dialog that's still visually open with `aria-modal="true"`. Confirmed via grep: no
`inert`, focus-trap, or `Tab`-key handling exists anywhere in `src/components`, `src/quiz`, or
`src/lib`. Mild in practice — both dialogs have only 2-4 focusable elements and Escape/click-outside
still close them — but a real, unaddressed remainder of docs/42 §5's original suggestion. Fix:
one shared `useFocusTrap` hook, reused by both dialogs rather than a third bespoke partial
implementation. Not urgent enough for its own PR; reasonable to bundle with the next a11y-adjacent
change.

## Docs consistency — seven confirmed findings, all fixed in this pass

Unlike the other four lenses, this one had real work to do: docs can drift even when the code
they describe hasn't moved, if a fix or a rename lands without every doc that references it being
updated. All seven were verified directly against current code (not doc-vs-doc comparison) and
were mechanical enough to fix immediately as part of this same pass, consistent with docs/50's
precedent of fixing cheap docs findings inline rather than deferring them:

1. ✅ **`docs/07-roadmap.md` self-contradicted on HSK3's status** — its "Explicitly deferred"
   section still listed "HSK 3 support (data doesn't exist yet)" while Phase 1 earlier in the same
   doc narrates HSK3 being fully built, and `src/lib/hsk-level.ts` confirms it's live. Leftover
   line never reconciled against the doc's own later phases. Removed.
2. ✅ **`docs/44-audit-quiz-ux-gaps.md` was missing ✅ Fixed annotations** for items resolved by
   commit `91cd9c9` (#38): the `ChoiceQuizRunner` dual-sticky-bar overlap (item #12, previously
   "unconfirmed, worth a look") and the four a11y gaps in "Re-audit notes" (`aria-live` on the
   Missed counter, `aria-pressed` on Match tiles, keyboard row navigation). All confirmed present
   in code; annotated inline.
3. ✅ **`docs/10-color-palette.md` still cited non-existent `<PillButton>`/`<PercentBadge>`
   components** — docs/08's own component inventory (corrected by docs/43) already says there's no
   such component, just a `pillClasses()` helper and inline JSX; docs/10 had the same wrong claim
   living independently and was missed by that earlier fix. Reworded to match.
4. ✅ **`docs/10-color-palette.md` had a broken relative link** to `AllWordsTabs.tsx` — the file
   moved to `src/components/vocab/AllWordsTabs.tsx` in docs/50's `src/components/` reorg; the link
   still pointed at the old flat path. Fixed.
5. ✅ **`docs/21-vercel-deploy.md` pointed at a stale source path** for `send-email.ts` — moved to
   `src/lib/auth/send-email.ts` in docs/50's `src/lib/` reorg. This is the one deploy doc a new
   contributor would actually follow to set up env vars; fixed.
6. ✅ **`docs/09-pages.md`'s header description omitted the Custom Quiz link** — `AppHeader.tsx`
   and docs/08's own inventory both list it; docs/09's intro paragraph didn't. Added.
7. ✅ **`docs/04-data-pipeline.md` described the seed upsert key without `source`** — the real
   Prisma unique constraint is `@@unique([chapterId, chinese, source])`, and `seed.ts` upserts on
   that full compound key (`source` distinguishes a chapter's "New Words" row from its "dialog"
   row for the same Chinese text). Lower severity as a tier-2/historical doc, but still
   cross-linked from docs/05; corrected.

## What this run says about the playbook itself

Working as intended: three lenses correctly reported "re-checked, still clean" instead of padding
with manufactured findings; one lens (frontend) caught a real gap and also caught itself about to
write up a false one before it got written down; the docs lens is the one that found genuine,
previously-unnoticed drift, which is exactly the kind of thing a lens-based split is supposed to
surface (nothing else was positioned to check docs against code specifically). Total net-new
actionable items from this round: one Low a11y finding (frontend, still open) and seven docs
staleness fixes (docs consistency, all fixed above).
